# Context Platform — Token-Efficiency & Search Roadmap

Tracks features aimed at one goal: let Claude Code (and any other agent) get
oriented in a codebase and recall past decisions using as few tokens as
possible, via persistent memory + code-intelligence search instead of
re-reading files from scratch.

Status legend: ✅ done · 🚧 in progress · 📋 planned (not started)

## ✅ Done

- Hybrid search (lexical FTS5 + vector cosine + graph proximity + recency + memory signal), token-budgeted context packs (`ContextPackBuilder`).
- Symbol-level incremental indexing (`SymbolDiffer`), tree-sitter based AST parsing.
- Persistent typed memory (Decision/Discovery/BugFix/Feature/...) with reinforcement/supersession, extracted from session summaries via LLM.
- Session lifecycle: start/prompt/tool-use/end hooks, `SessionSummary` (Completed/Discovered/Decisions/OpenIssues/NextSteps/ChangedFiles).
- Periodic mid-session summarization (`SessionSummaryScheduler`) — a session no longer needs to formally "end" to produce a memory. Batches on event count (not just elapsed time) to avoid noise memories.
- MCP tools exposing all of the above to Claude Code directly (`context_search`, `code_search`, `symbol_search`, `memory_search`, `graph_impact`, etc.) + an installable `context-memory` skill teaching Claude to prefer them over re-deriving context.
- Dashboard (Angular): Projects, Overview, Search, Memories, Sessions, Graph (impact/blast-radius), Settings (provider config, reindex schedule, Claude integration installer, folder-browser project creation), System (live health/job status).
- Live SignalR updates: reindex progress, project stats, session-summary/memory-created activity — panels refresh without polling or reload.
- Cross-platform hook installer (fixed a real bug: was double-registering both `.ps1` and `.sh` commands when a repo was set up from more than one OS, causing every hook to fire twice).
- **Session titles** — `SessionSummary` gets an LLM-generated short descriptive title (git-commit-subject style), shown in the Sessions list/detail instead of a bare timestamp; deterministic non-empty fallback when offline. Live-verified; also fixed a real bug found in verification (`SessionSummaryParser`'s header regex didn't tolerate the markdown headings — `### TITLE:` — this model reliably produces on real-sized sessions, silently discarding the whole parse).
- **Structured memory (Facts)** — `Memory.FactsJson`: 2-5 short, atomic, standalone bullet facts extracted alongside the existing prose `Body`, for when a search result needs to say something useful in very few tokens. Rendered as a bullet list above the body in the Memories tab. Live-verified against real extracted memories.
- **Per-file semantic summary ("file wiki")** — indexing now also generates a short natural-language description of each file (`IFileSummarizer`, no-op under the noop LLM provider) and embeds it as its own searchable chunk (`Chunk.SymbolId = null`). Live-verified: a real reindex produced real file-level search hits with natural-language snippets. File-kind hits render distinctly in the Search tab.
- Fixed `dotnet run`/`dotnet build` never actually serving the Dashboard (`Context.Host.csproj` only copied the built Angular output into `wwwroot/` at publish time, never for a plain run — found live while verifying the three features above).
- **Graph tab visualization** — an actual node/edge graph (vis-network), not just text impact lists: clicking a node shows its connections plus an info panel, "Re-center" re-fetches the neighborhood around the clicked node. Live-verified via Playwright against the real dashboard+host.
- **Obsidian-style full-project graph view** — a Search/Full-graph toggle in the Graph tab; Full graph renders every node/edge in the project (`GET /api/graph/full`, `IGraphTraversal.FullGraphAsync`), not just a hop-bounded neighborhood. Dense renders (>300 nodes) drop per-edge labels/arrows and use lighter physics — real project graph is 2483 nodes/2793 edges. "Show blast radius" on a clicked node jumps into the focused search view. Live-verified.
- **Codemem-style hybrid pack re-ranking refinements** — kind-based ranking bonus (decision/feature/bugfix prioritized) in `HybridScorer.ApplyMemoryTypeBonus`, plus query-intent detection (`QueryIntent`: pending-work/recall keyword routing) in `ContextPackBuilder`/`ContextEngine`.
- **Embedding cache cross-provider invalidation** — `Embedding` is now keyed by `(ContentHash, Provider)` instead of `ContentHash` alone; switching embedding providers no longer risks reusing a stale cross-provider vector.
- **Call-graph extraction fix** — tree-sitter `Calls` queries only matched bare-identifier invocations (`Foo()`), never member-access calls (`this.Foo()`, `obj.Foo()`, all LINQ) or method-group references (`.Select(Foo)`) — real symbols showed zero callers despite genuine usage. Fixed across C#/JS/TS/Python parsers.
- **Docker container → host Ollama networking** — `OllamaHostFallbackHandler` detects running-in-container and probes `host.docker.internal`/`172.17.0.1` as fallbacks when the configured host is unreachable. Confirmed live that this specific Rancher-Desktop-on-Windows setup still doesn't have a working candidate (its `host-gateway` maps both fallbacks to the same unreachable IP) — bare-metal remains the only verified-working path; the mitigation is real but doesn't fully close this environment's gap.
- **Microsoft.Extensions.AI provider migration** — `Context.Providers`' `ILlmProvider`/`IEmbeddingProvider` implementations now wrap `IChatClient`/`IEmbeddingGenerator<string, Embedding<float>>` (OllamaSharp, Anthropic.SDK, official OpenAI SDK) instead of hand-rolled HTTP calls; the app-facing interfaces are unchanged. Option registration refactored to match: `ProjectSettingsService` layers appsettings defaults → DB → `.claude/context-platform.local.json`; `Program.cs` builds `HybridScoringOptions`/`HybridSearchOptions`/`ContextPackOptions` from `IConfiguration`; `HybridScorer`/`HybridSearchEngine`/`ContextPackBuilder` accept an `IOptionsMonitor<T>` overload so retrieval-tuning config can change without a restart (provider *selection* — noop/ollama/openai — still can't hot-swap, see the item below). Live-verified: a real `/api/search` hit went through the new `OllamaEmbeddingProvider` end-to-end.

## 📋 Planned (not started)

- **Dashboard → Context.Dashboard (VS Angular/esproj + SpaProxy) migration** — moving `apps/dashboard` off the hand-rolled MSBuild `Exec`-target build (`Context.Host.csproj`'s `BuildDashboard`/`CopyDashboardToWwwroot` targets) onto a `dashboard.esproj`/SpaProxy-based setup, the same shape `dotnet new angular` produces, so `ng serve` runs via `Microsoft.AspNetCore.SpaProxy` instead of a pre-build `ng build`. A previous session scaffolded `apps/host/Context.Dashboard/` and `apps/dashboard/dashboard.esproj` for this (left on disk, untracked, not wired into `ContextPlatform.slnx`) — picking this up should start from reviewing that scaffold rather than from scratch. Explicitly deferred; do this in its own isolated pass.
- **System.CommandLine 2.0 GA migration** — `Context.Cli` is pinned to `2.0.0-beta4.22272.1`; the `Command`/`RootCommand`/`Argument`/`Option` builder API changed completely by 2.0 GA (`AddArgument`/`AddOption`/`SetHandler`/`InvocationContext` are all gone). Bumping the package alone breaks the whole CLI — needs a dedicated rewrite pass of `apps/cli/Context.Cli/Program.cs`, not a version-bump-and-fix.
- **ModelContextProtocol.AspNetCore major version bump** — pinned to the `0.2.0-preview.3` this project started on; a `2.2.0` bump was tried alongside the AI-provider migration and reverted (unrelated scope, unverified API surface). Worth its own pass to check what changed in `AddMcpServer()`/`WithHttpTransport()`/`MapMcp()` before upgrading.
- **Live settings reload — provider *selection* hot-swap** — `Context.Retrieval`'s tuning knobs (scoring weights, rerank top-K, etc.) already hot-reload via `IOptionsMonitor<T>` (see above), but `AddContextProviders` still picks a FIXED concrete `IEmbeddingProvider`/`ILlmProvider` type via a one-time switch on the provider name string at startup — switching noop/ollama/openai/anthropic still needs a Context.Host restart. Needs either a routing/proxy provider that dispatches to the right concrete implementation per current settings, or resolving providers by name from a keyed service collection at call time. Not yet scoped into an implementation plan.
- **Vector store migration (Microsoft.Extensions.VectorData)** — replace the EF-Core-backed `Embedding`/`IEmbeddingRepository` (manual cosine-similarity search) with `VectorStoreCollection<TKey,TRecord>` (`SqliteCollection` locally, `QdrantCollection` or similar for a hosted setup), using `[VectorStoreKey]`/`[VectorStoreData]`/`[VectorStoreVector]`-attributed records. Substantially larger than the chat/embedding-generator swap above — touches `Context.Infrastructure`'s repository layer and `HybridSearchEngine`'s core vector-search path. Not started; flagged during the Microsoft.Extensions.AI migration as the natural next increment, deliberately not bundled into it.

## Notes

- Real per-project data (this repo dogfooding itself) has repeatedly surfaced actual bugs during live testing that static review missed — keep verifying live (build + test + actually run it) rather than trusting compilation alone before marking anything done here.
- Comparison reference for memory/retrieval design: [codemem](https://github.com/kunickiaj/codemem) — FTS5+BM25 lexical, sqlite-vec semantic, hybrid re-rank with kind bonus, structured Summary/Facts/Narrative/Concepts per memory item, `files_read`/`files_modified` provenance per memory, batched raw-event ingestion before its observer runs (the same reasoning behind this project's event-count threshold above).
