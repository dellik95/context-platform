Retries

Off by default: a failed job is already retried later by the job queue. When on, only connection errors, 408 and 5xx are retried, each wait doubling from the base delay. A 429 or a timeout is never retried. Retry failed provider calls

Stale sessions

Ends an Active session (with a final summary and memory extraction) after no new activity for this long — protects against a killed terminal or crashed CLI process leaving a session Active forever. Enable stale-session cleanup

Raw session events

Once a batch of raw session events is folded into a summary, it's no longer needed by the memory pipeline — enabling this deletes it from the database. The session detail view and the MCP recall tool then no longer show raw events older than the latest summary. Delete raw session events after summarization

Hook invocations

Every hook call (SessionStart, UserPromptSubmit, PostToolUse, Stop, PostCompact, SessionEnd) is logged for the dashboard's live activity feed and never cleaned up elsewhere — enabling this periodically deletes invocations older than the window below. Enable hook invocation cleanup
